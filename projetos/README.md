## 1. Objetivo do trabalho

Cada grupo deverá desenvolver um aplicativo mobile funcional utilizando **React Native com Expo** e **SQLite** para armazenamento local dos dados.

O objetivo é aplicar, de forma integrada, os conhecimentos desenvolvidos durante a disciplina, passando pelas etapas de definição da ideia, planejamento, desenvolvimento da interface, implementação das funcionalidades, persistência de dados e apresentação do aplicativo.

A aplicação deverá resolver um problema ou atender a uma necessidade definida pelo grupo. O projeto deverá ser desenvolvido de maneira colaborativa, utilizando controle de versão e permitindo identificar a participação dos integrantes.

## 4. Tecnologias obrigatórias

Todos os grupos deverão utilizar:

### React Native

Utilizado para o desenvolvimento da aplicação mobile e construção dos componentes da interface.

### Expo

Utilizado para criação, execução e desenvolvimento do projeto React Native.

### SQLite

Utilizado como banco de dados local da aplicação.

O banco de dados deverá realmente ser utilizado pela aplicação para armazenar e recuperar informações. Não será considerado suficiente apenas criar uma tela simulando um cadastro.

## 5. Requisitos mínimos do aplicativo

Independentemente do tema escolhido, todos os projetos deverão possuir:

### 5.1 Interface

O aplicativo deverá possuir uma interface organizada e adequada para dispositivos móveis. Deverão ser utilizados componentes do React Native, como, quando apropriado:

- `View`;
- `Text`;
- `TextInput`;
- `Button` ou componentes de botão;
- `ScrollView` e/ou `FlatList`;
- componentes de navegação entre telas.

### 5.2 Cadastro de informações

O usuário deverá conseguir inserir informações no aplicativo.

> Exemplo: em um aplicativo de controle financeiro, o usuário poderá cadastrar uma despesa informando descrição, valor, categoria e data.

### 5.3 Consulta

O aplicativo deverá apresentar os dados cadastrados no SQLite.

> Exemplo: uma tela poderá apresentar uma lista de todas as despesas cadastradas.

### 5.4 Alteração

O usuário deverá conseguir selecionar um registro e alterar suas informações.

### 5.5 Exclusão

O usuário deverá conseguir excluir um registro.

### 5.6 Persistência

Os dados deverão permanecer armazenados no SQLite mesmo depois que o aplicativo for fechado e aberto novamente.

## 6. Estrutura sugerida do aplicativo

Cada grupo poderá adaptar a estrutura ao seu tema, mas recomenda-se uma organização semelhante a:

- **Tela 1 — Início:** apresentação do aplicativo; acesso às principais funcionalidades.
- **Tela 2 — Listagem:** apresentação dos registros cadastrados; opção de visualizar, editar ou excluir.
- **Tela 3 — Cadastro:** formulário para inclusão de novos registros.
- **Tela 4 — Edição:** formulário para alteração dos registros existentes.
- **Banco SQLite:** criação das tabelas; inserção, consulta, atualização e exclusão.

A estrutura exata (nomes de telas, campos e tabelas) está detalhada no README da categoria escolhida.

**Entrega esperada:** um documento curto contendo a proposta do projeto. Também deverá ser informado o repositório GitHub do grupo, caso já esteja criado.

**Resultado esperado:** ao final desta etapa, deverá estar definido **quem fará o projeto + qual será o aplicativo + para quem ele será desenvolvido + quais serão suas principais funcionalidades**.

### ENTREGA 2 — Protótipo e estrutura do aplicativo

**Data: 14/09/2026**

### ENTREGA 3 — Aplicativo funcional

**Data: 19/10/2026**

Nesta etapa deverá ser entregue a maior parte do desenvolvimento do aplicativo. O SQLite deverá estar integrado ao projeto.

O aplicativo deverá possuir:

- banco SQLite funcionando;
- criação das tabelas;
- cadastro de registros;
- consulta dos registros;
- alteração dos registros;
- exclusão dos registros;
- navegação funcionando;
- interface funcional;
- validação básica dos dados;
- tratamento básico de erros.

Nesta etapa, o projeto deverá apresentar um **CRUD completo**.

**CRUD:** **C** — Create (criar/cadastrar) · **R** — Read (consultar/listar) · **U** — Update (atualizar/editar) · **D** — Delete (excluir).

**Resultado esperado:** o grupo deverá apresentar uma versão funcional do aplicativo, permitindo realizar as principais operações sobre os dados armazenados no SQLite.

## 9. Controle de versão e trabalho em equipe

O projeto deverá ser desenvolvido de maneira colaborativa.

Recomenda-se que cada integrante realize contribuições no repositório do grupo, permitindo acompanhar o desenvolvimento. O grupo deverá evitar que apenas um integrante desenvolva todo o projeto. Sempre que possível, as tarefas deverão ser divididas entre os integrantes.

Exemplo de divisão para quatro integrantes:

| Integrante | Responsabilidades |
|------------|-------------------|

| Integrante 2 — Banco de dados | SQLite, criação das tabelas, consultas, operações CRUD. |

| Integrante 4 — Integração e documentação | Integração das funcionalidades, testes, README, documentação, apoio na apresentação. |

Essa divisão é apenas uma sugestão. Todos os integrantes devem compreender o funcionamento geral do aplicativo.

## 13. Orientação final

O projeto deve ser encarado como um processo de desenvolvimento em etapas. A primeira entrega não exige um aplicativo pronto; ela define a proposta.
